КАК СОЗДАТЬ API (HTTP-СЕРВИС) В 1С:КОНФИГУРАТОРЕ


Инструкция повторяет требования задания 5 (Прил_5_ОЗ_КИМ): эндпоинт GET /notes,
ответ с полями id, title_user, content, formatted_date, коды 200 / 400 / 500.


ШАГ 1. ОТКРЫТЬ КОНФИГУРАТОР

1. Запустить 1С в режиме Конфигуратор (не Предприятие).
2. Открыть конфигурацию: Конфигурация -> Открыть конфигурацию.
3. Включить возможность изменения (если база в режиме "только чтение"):
   Конфигурация -> Поддержка -> Настройка поддержки -> Включить возможность изменения.


ШАГ 2. СОЗДАТЬ HTTP-СЕРВИС

1. В дереве конфигурации: правой кнопкой на "Общие -> HTTP-сервисы" -> Добавить.
2. Задать имя объекта, например: СервисЗаметок.
3. В свойствах объекта указать Корневой URL, например: notes_service.
4. Сохранить (Ctrl+S) - конфигурация должна скомпилироваться без ошибок.


ШАГ 3. ДОБАВИТЬ ШАБЛОН URL

1. В объекте СервисЗаметок раскрыть ветку "Шаблоны".
2. Добавить новый шаблон:
   - Имя: Заметки
   - Шаблон URL: /notes
3. В этом шаблоне добавить метод:
   - HTTP-метод: GET
   - Имя обработчика: ПолучитьЗаметки


ШАГ 4. НАПИСАТЬ КОД ОБРАБОТЧИКА

Открыть модуль HTTP-сервиса (двойной клик на СервисЗаметок -> "Модуль")
и вставить следующий код:

----------------------------------------------------------------------
Функция ПолучитьЗаметки(Запрос)

	// Путь к JSON-файлу с данными. "Z:\..." - это путь, как его видит 1С внутри
	// Wine (Z: соответствует корню Linux-диска "/"). На реальном Windows-компьютере
	// это будет обычный путь вида "C:\Users\...\notes.json".
	ПутьКФайлу = "Z:\home\dissy\1cc\notes.json";

	Попытка
		ТекстовыйДокумент = Новый ТекстовыйДокумент;
		ТекстовыйДокумент.Прочитать(ПутьКФайлу, КодировкаТекста.UTF8);

		МассивЗаметок = ПрочитатьЗначениеJSON(ТекстовыйДокумент.ПолучитьТекст());

		ЗаписьJSON = Новый ЗаписьJSON;
		ЗаписьJSON.УстановитьСтроку();
		ЗаписатьJSON(ЗаписьJSON, МассивЗаметок);
		ТекстОтвета = ЗаписьJSON.Закрыть();

		Ответ = Новый HTTPСервисОтвет(200);
		Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
		Ответ.УстановитьТелоИзСтроки(ТекстОтвета, КодировкаТекста.UTF8);
		Возврат Ответ;

	Исключение
		Ответ = Новый HTTPСервисОтвет(500);
		Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
		Ответ.УстановитьТелоИзСтроки(
			"{""error"": ""Файл с заметками не найден или повреждён""}", КодировкаТекста.UTF8);
		Возврат Ответ;
	КонецПопытки;

КонецФункции
----------------------------------------------------------------------

Пояснение:
- ПутьКФайлу - указываешь путь к тому же файлу, который использует Python-вариант
  (/home/dissy/1cc/notes.json). Это и есть источник данных - никакого справочника
  1С тут не задействовано.
- ТекстовыйДокумент.Прочитать(...) - читает весь файл как текст (так же, как
  open(...).read() в Python).
- ПрочитатьЗначениеJSON(...) - разбирает текст в массив структур 1С (аналог
  json.load в Python).
- Сразу после этого ЗаписатьJSON сериализует обратно в строку - это заодно
  проверяет, что JSON валидный, и приводит его к одинаковому виду перед отправкой.
- Если файла нет, или в нём не JSON (ошибка парсинга) - сработает Исключение,
  и клиент получит 500 с понятным сообщением вместо падения без объяснений.
- Если в файле лежит пустой массив [] - весь код отработает штатно и вернёт
  200 с телом [], как и требует ТЗ для случая "данных нет".


ВАЖНО: "ОТЛАДКА HTTP-СЕРВИСОВ" ТРЕБУЕТ НАСТОЯЩИЙ ВЕБ-СЕРВЕР

На практике оказалось, что встроенная "Отладка HTTP-сервисов" в 1С не поднимает
сервер сама по себе - она ПОДКЛЮЧАЕТСЯ к уже опубликованному HTTP-сервису на
реальном веб-сервере (Apache или IIS) с установленным модулем-коннектором 1С.
Если такого веб-сервера на машине нет - 1С пишет "Веб-серверы не обнаружены",
и дальше этот путь не сработает.

Если Apache/IIS с модулем 1С на твоей машине есть - используй раздел
"ЕСЛИ НУЖНА ПОСТОЯННАЯ ПУБЛИКАЦИЯ" в конце документа. Если нет (как было
у нас) - используй рабочую альтернативу ниже: она не требует веб-сервера вообще.


РАБОЧАЯ АЛЬТЕРНАТИВА: ЛОКАЛЬНЫЙ СЕРВЕР НА PYTHON + 1С ОБРАЩАЕТСЯ К НЕМУ

Это проверенный вариант, который реально работает без Apache/IIS. Здесь API
реализует не сам 1С, а отдельный Python-процесс; 1С просто обращается к нему
по HTTP, как к любому внешнему серверу.

Сервер на Python (app.py):

----------------------------------------------------------------------
import json
from pathlib import Path

from fastapi import FastAPI
from fastapi.responses import JSONResponse

app = FastAPI(title="Notes API")

NOTES_FILE = Path("/home/dissy/1cc/notes.json")  # на Windows - обычный путь,
                                                   # например C:\notes\notes.json

@app.get("/notes")
def get_notes():
    try:
        with open(NOTES_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        return JSONResponse(
            status_code=500,
            content={"error": "Файл с заметками не найден"},
        )
----------------------------------------------------------------------

Запуск:

   uvicorn app:app --host 127.0.0.1 --port 8000

(подробности по установке/запуску на Windows, включая случай, когда pip не
в PATH - см. файл "Дополнение_Локальный_сервер").

Код в 1С, который к нему обращается (из обработки "Синхронизация заметок",
вызывается по кнопке):

----------------------------------------------------------------------
Процедура СинхронизироватьНаСервере()
	Сервер = "127.0.0.1";
	Порт = 8000;
	Путь = "/notes";

	Соединение = Новый HTTPСоединение(Сервер, Порт,,,,, Ложь); // Ложь = обычный HTTP
	Ответ = Соединение.Получить(Новый HTTPЗапрос(Путь));

	Если Ответ.КодСостояния <> 200 Тогда
		Сообщить("API вернул код ошибки: " + Ответ.КодСостояния);
		Возврат;
	КонецЕсли;

	МассивЗаметок = ПрочитатьЗначениеJSON(Ответ.ПолучитьТелоКакСтроку());

	Для Каждого Заметка Из МассивЗаметок Цикл
		Ссылка = Справочники.Заметки.НайтиПоКоду(Заметка.id);
		Если Ссылка.Пустая() Тогда
			Элемент = Справочники.Заметки.СоздатьЭлемент();
			Элемент.Код = Заметка.id;
		Иначе
			Элемент = Ссылка.ПолучитьОбъект();
		КонецЕсли;
		Элемент.Наименование = Заметка.title_user;
		Элемент.Содержание = Заметка.content;
		Элемент.Записать();
	КонецЦикла;

	Сообщить("Синхронизация завершена");
КонецПроцедуры
----------------------------------------------------------------------

Важно: "Защищённое соединение" (последний параметр HTTPСоединение) должно быть
Ложь, потому что локальный сервер работает по обычному HTTP, а не HTTPS
(HTTPS нужен был только для raw.githubusercontent.com, с реальным GitHub).

Порядок запуска (чтобы всё заработало):

1. Запустить Python-сервер (окно с ним держать открытым - это и есть "веб-сервер").
2. Проверить, что отвечает: curl http://127.0.0.1:8000/notes или открыть в браузере.
3. Запустить 1С:Предприятие, открыть обработку "Синхронизация заметок".
4. Указать Сервер 127.0.0.1, Порт 8000, Путь /notes.
5. Нажать "Синхронизировать".


КОДЫ ОТВЕТОВ (СООТВЕТСТВИЕ ТЗ)

Ситуация                              | Что делает код
---------------------------------------|----------------------------------------
Есть данные                            | 200 + массив заметок
Справочник пуст                        | 200 + [] (цикл просто ничего не добавит)
Исключение при выборке                 | 500 + {"error": "..."}
Некорректный параметр запроса          | добавить проверку Запрос.ПараметрыЗапроса
                                        | в начале функции и возвращать
                                        | Новый HTTPСервисОтвет(400) при ошибке


ЕСЛИ НУЖНА ПОСТОЯННАЯ ПУБЛИКАЦИЯ (НЕ ТОЛЬКО ОТЛАДКА)

1. Администрирование -> Публикация на веб-сервере...
2. Выбрать веб-сервер (Apache/IIS, должен быть установлен и настроен заранее).
3. Отметить HTTP-сервис СервисЗаметок в списке публикуемых объектов.
4. После публикации сервис будет доступен по адресу вида:
   http://localhost/имя_базы/hs/notes_service/notes
   (используя модуль веб-сервера 1С).

Для сдачи задания на экзамене обычно достаточно встроенной отладки HTTP-сервисов
(Шаг 5) - она не требует настройки внешнего веб-сервера и запускается за пару
кликов.
