# Дополнение: локальный сервер (uvicorn) на Windows

Этот файл дополняет `Как_создать_API_на_Python.md` — отдельно про то, как
проверить/поставить/запустить сервер именно на Windows, с учётом того, что
команда `pip` может не быть видна напрямую (не добавлена в PATH), но при
этом работает через **Python Launcher** — команду `py`.

## Как понять, какой вариант у тебя работает

Открой командную строку (`cmd`) или PowerShell и попробуй по очереди:

```cmd
pip --version
```

- Если показало версию pip — значит `pip` работает напрямую, используй команды
  из раздела **"Вариант А"** ниже.
- Если пишет что-то вроде `'pip' is not recognized as an internal or external command`
  — `pip` не в PATH, используй раздел **"Вариант Б"** (через `py -m pip`).

Проверить, что сам Python Launcher (`py`) в принципе есть:

```cmd
py --version
```

Если и это не найдено — Python не установлен вообще, тогда сначала нужно
поставить сам Python (на экзамене он должен быть предустановлен — см. список ПО).

## Проверить, установлен ли uvicorn

### Вариант А — если `pip` работает напрямую

```cmd
pip show uvicorn
```

- Выведет версию и путь — пакет установлен.
- Выведет `WARNING: Package(s) not found: uvicorn` — не установлен, ставь (см. ниже).

### Вариант Б — если `pip` не распознаётся, но есть `py`

```cmd
py -m pip show uvicorn
```

Работает так же, как вариант А, просто вызывается через лаунчер `py`,
который сам найдёт нужный интерпретатор Python и его модуль `pip`.

## Установить uvicorn (и fastapi), если их нет

### Вариант А

```cmd
pip install fastapi uvicorn
```

### Вариант Б

```cmd
py -m pip install fastapi uvicorn
```

Если используешь виртуальное окружение (venv) — сначала его активируй:

```cmd
venv\Scripts\activate
```

и только потом выполняй команды установки (тогда `pip`/`py -m pip` поставят
пакеты именно в это окружение, а не в системный Python).

## Запустить сервер

### Вариант А

```cmd
uvicorn app:app --host 127.0.0.1 --port 8000
```

### Вариант Б (если команда `uvicorn` тоже не распознаётся напрямую)

```cmd
py -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Оба варианта делают одно и то же — отличие только в том, вызывается ли
программа напрямую по имени или через лаунчер `py -m ...`.

## Проверить, что сервер реально поднялся и отвечает

В соседнем окне командной строки (сервер в первом окне должен продолжать
работать, не закрывай его):

```cmd
curl http://127.0.0.1:8000/notes
```

Если `curl` не найден (бывает на старых Windows) — открой этот адрес
в обычном браузере: `http://127.0.0.1:8000/notes`. Если видишь JSON — сервер
работает.

Проверить, что процесс вообще запущен (аналог `pgrep` в Linux):

```cmd
tasklist | findstr python
```

Покажет все запущенные процессы Python, включая тот, где крутится uvicorn.

## Частые ошибки и что они значат

| Сообщение | Причина | Что делать |
|---|---|---|
| `'pip' is not recognized...` | pip не в PATH | Используй `py -m pip ...` (Вариант Б) |
| `'py' is not recognized...` | Python не установлен или не в PATH | Переустановить Python с галочкой "Add to PATH" |
| `ModuleNotFoundError: No module named 'uvicorn'` | Пакет не установлен в этом окружении | `py -m pip install uvicorn` (проверь, что активен тот же venv, что и при запуске) |
| В 1С: "Не могу установить соединение" | Сервер (uvicorn) не запущен или закрыт | Снова выполнить команду запуска сервера, окно с ним держать открытым |
| Сервер запустился, но на другом порту | При запуске не указали `--port 8000`, либо порт занят другим процессом | Указать порт явно, либо в 1С поменять поле "Порт" на тот, что реально вывелся в консоли |
