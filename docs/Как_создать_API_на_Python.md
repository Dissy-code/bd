# Как создать API на Python (FastAPI) — вариант без 1С

Та же задача, что и в документе про 1С (`Как_создать_HTTP_сервис_в_1С.md`):
эндпоинт `GET /notes`, ответ с полями `id`, `title_user`, `content`, `formatted_date`,
коды 200 / 400 / 500. Только здесь всё делает отдельный Python-процесс, а 1С потом
просто стучится в него по HTTP.

## Почему Python разрешён

В списке ПО на экзамене прямо указаны: **Python 3.12+, FastAPI, PyCharm/VS Code**.
Поэтому этот путь официально допустим наравне с HTTP-сервисом в самом 1С.

## Шаг 1. Установить окружение

```bash
mkdir notes_api && cd notes_api
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install fastapi "uvicorn[standard]"
```

## Шаг 2. Подготовить данные

Самый простой вариант — не городить базу данных, а держать данные в обычном
JSON-файле на диске (`notes.json`):

```json
[
  {
    "id": "00001",
    "title_user": "Конференция ИТ - user25",
    "content": "Обсуждение планов на 2027 год",
    "formatted_date": "15.03.2027"
  },
  {
    "id": "00002",
    "title_user": "Совещание по проекту - user42",
    "content": "Статус разработки API",
    "formatted_date": "02.04.2027"
  }
]
```

Редактировать этот файл — и есть "работа с данными": никакой базы, никакого SQL,
сервер просто перечитывает файл при каждом запросе.

## Шаг 3. Код сервера (`app.py`)

```python
import json
from pathlib import Path

from fastapi import FastAPI
from fastapi.responses import JSONResponse

app = FastAPI(title="Notes API")

NOTES_FILE = Path(__file__).parent / "notes.json"


@app.get("/notes")
def get_notes():
    try:
        with open(NOTES_FILE, "r", encoding="utf-8") as f:
            return json.load(f)
    except FileNotFoundError:
        return JSONResponse(
            status_code=500,
            content={"error": "Файл с заметками не найден"},
        )
```

### Разбор кода построчно

- `app = FastAPI(...)` — создаёт приложение. Это объект, который знает про все
  маршруты (эндпоинты) и умеет сам превращать Python-данные в JSON-ответ.
- `@app.get("/notes")` — декоратор: говорит FastAPI "когда придёт GET-запрос
  на `/notes`, вызови вот эту функцию ниже".
- `def get_notes():` — обычная Python-функция. То, что она **возвращает**,
  FastAPI сам сериализует в JSON и отправит клиенту — руками JSON собирать не надо.
- `open(NOTES_FILE, ...)` + `json.load(f)` — читает файл с диска и превращает
  текст в Python-объект (список словарей) за одну строку.
- `return json.load(f)` — отдаём этот список как есть; FastAPI увидит, что
  это `list`, и автоматически завернёт в JSON-ответ с кодом `200`.
- `except FileNotFoundError` — если файла нет (например, кто-то удалил/переименовал),
  вместо падения с ошибкой 500 без объяснений отдаём осмысленный ответ:
  `JSONResponse(status_code=500, content={...})` — это способ явно указать код
  ответа и тело, а не полагаться на автоматику.

Если файл есть, но список внутри пустой (`[]`) — функция просто вернёт пустой
список, FastAPI отдаст `200` с телом `[]`. Это ровно то поведение, которое
требует ТЗ для случая "данных нет" — отдельно обрабатывать не нужно, оно уже
получается само собой из логики `json.load`.

## Шаг 4. Запустить сервер

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

- `uvicorn` — программа, которая реально слушает порт и превращает входящие
  HTTP-запросы в вызовы функций FastAPI (сам FastAPI — только "конструктор"
  приложения, он не умеет слушать сеть сам по себе).
- `app:app` — "в файле `app.py` возьми переменную `app`".
- `--port 8000` — на этом порту сервер будет доступен: `http://127.0.0.1:8000/notes`.

## Шаг 5. Проверить вручную

```bash
curl http://127.0.0.1:8000/notes
```

Либо просто открыть эту ссылку в браузере — увидишь JSON.

## Шаг 6. Подключить 1С

В 1С (обработка/HTTP-сервис) указываешь:
- Сервер: `127.0.0.1`
- Порт: `8000`
- Путь: `/notes`

и делаешь обычный `HTTPСоединение` + `HTTPЗапрос`, как в документе про интеграцию
с 1С — код на стороне 1С не меняется, независимо от того, кто отвечает на
HTTP-запрос: сам 1С (HTTP-сервис) или Python-процесс (FastAPI).

## Сравнение: 1С HTTP-сервис vs Python FastAPI

| | HTTP-сервис в 1С | FastAPI на Python |
|---|---|---|
| Где пишется код | В Конфигураторе, BSL | В обычном `.py` файле |
| Нужен отдельный процесс | Нет, работает внутри 1С | Да, `uvicorn` запускается отдельно |
| Доступ к данным | Напрямую к справочникам 1С | К своему файлу/БД (отдельно от 1С) |
| Что проще показать на защите | Один объект в дереве конфигурации | Один файл кода, видно сразу всё |
| Разрешено на экзамене | Да (1С в списке сред) | Да (Python/FastAPI в списке явно) |

Оба варианта равноценны для задания 5 — выбирай тот, с которым увереннее
работаешь под давлением времени на экзамене.
